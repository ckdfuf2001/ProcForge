# M10-spec 초안 — OpenCode 클라이언트 실행 (유사 분석→자동 실행)

> 구현 착수 조건: M10-0 실측 완료 + 판정자 승인.
> M10-0 문서(`docs/M10-0-opencode-api.md`)의 실측 필요 항목과 1:1로 연결된다
> (§5 각 항목에 [실측 의존] 표시).

## §1 목표 (1차 범위)
- 유사 분석: 기존 절차서 중 이번 요청과 비슷한 것을 찾아낸다.
- 재분석: 찾은 절차서를 이번 요청에 맞게 고쳐 쓴다 (새 분해가 아님).
- 단계별 가이드 UI: 고친 절차서를 사람이 단계마다 확인·진행한다.
- 순차 자동 실행: 확정된 절차서를 그대로 끝까지 실행한다.
- 2차 (범위 밖, 이번에 만들지 않음): 병렬 실행, To-Do 운영,
  교훈 집계 (M9-2 §5 판정 4와 동일 — M9-3 후보).

## §2 구조
- Proof는 OpenCode 서버의 클라이언트다. 모델 공급자는 OpenCode이며,
  Proof가 직접 LLM을 호출하지 않는다.
- 기존 MCP 표면(`pf_*` 21종)은 불변. M10 기능은 App층 신규 메서드 +
  UI 화면 추가로만 들어간다 (새 MCP 도구 추가 없음).
- OpenCode 연결은 `PROOF_OPENCODE_URL`·`PROOF_OPENCODE_MODE`·
  `PROOF_OPENCODE_TOOL_PREFIX` 3종 (M8-1-dogfood §1, UI 터미널 설정).

## §3 흐름별 데이터
- 유사 분석 입력: `procedures/<name>/procedure.json` (목표·노드),
  `runs/<runId>/report.json` (성공 이력), `metrics.json` (규모),
  `by-procedure/<name>/latest.json` (최근 상태). — 판정 1 [실측 의존 없음]
- 가이드 단계 상태: 세션 단위 진행 기록 (신규, `.procforge` 아래).
  형식은 판정 2에서 정한다.
- 자동 실행 시 승인·취소·실패 처리: 기존 `uiRun`·`uiRunApprove`·
  `uiRunCancel` 경로를 그대로 쓴다 (재사용, 신규 실행기 없음).
  OpenCode 쪽 권한(`permission.updated`)과 Proof 쪽 승인 2중 승인 흐름은
  판정 3에서 정한다 [실측 의존].

## §4 구현 커밋 분할안
- M10-1 유사 분석 조회 (읽기 전용): 절차서 목록+최근 실행 요약 API 1개.
  테스트: ① 빈 저장소 빈 목록 ② 2회 실행 절차서가 latest 기준 정렬.
- M10-2 재분석 초안 생성: 기존 절차서 복사+요청 반영 diff 미리보기.
  테스트: ① 원본 무손상 ② diff 항목 수 일치.
- M10-3 단계별 가이드 UI: 단계 상태 저장·조회. 테스트: ① 중단 후 재개 시
  같은 단계 ② 완료 단계 건너뛰기.
- M10-4 순차 자동 실행 연결: 기존 uiRun 경로 호출 + OpenCode 세션 연결.
  테스트: ① fake OpenCode 서버로 끝까지 실행 ② 취소 시 양쪽 정리. [실측 의존]
- M10-5 문서: DEV-GUIDE §8 M10 [x] + 본 사양 판정 반영.

1. 유사도 기준 — A안: 노드 목표 텍스트 유사도. B안: metrics 규모+성공 이력 가중.
   추천: B안 (실행 기록 재사용이 M9-2 취지). [실측 의존 없음]
2. 가이드 단계 상태 형식 — A안: `runs/<runId>/guide.json`.
   B안: 세션 events 확장. 추천: A안 (run 기록과 동거, 조회 1회).
   [실측 의존 없음]
3. 2중 승인 흐름 — A안: OpenCode 권한 먼저, Proof 승인 나중.
   B안: Proof 승인으로 OpenCode 권한 자동 응답. 추천: 판단 보류,
   실측(권한 왕복 지연·응답값 의미) 후 결정. [실측 의존]
4. 자동 실행 중 OpenCode 세션 끊김 처리 — A안: 즉시 중단+fail.
   B안: 재연결 후 재개. 추천: A안 (재개 의미가 모델 상태에 달려 있어
   B안은 2차로). [실측 의존]
5. M10-1 조회 범위 — A안: 로컬 저장소만. B안: 원격 core 포함.
   추천: A안 (원격 core 하이드레이트 비용이 큼). [실측 의존 없음]

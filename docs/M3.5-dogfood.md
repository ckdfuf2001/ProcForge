# M3.5 실사용 테스트 (dogfood) 계획·기록

상태: 1차 실측 완료 (단일 모델). 2종 비교·토큰 통계는 사용자 환경에서 보완 필요.
측정 후 "결론" 절을 채우고, 코드 수정은 instruction 문구·description에 한정한다.

## 0. 실측 조건 (2026-10-10)

- 호스트: Muse Spark (muse-spark-1.3, 단일 모델 — 2종 비교 불가, 6회 중 3회 상당만 수행).
- PPT MCP: `pptx-mcp-server` 0.5.1 (pip 설치, PowerPoint 불필요).
- xlsx 읽기 도구 없음 → 호스트가 python(openpyxl)으로 대역 집계 (resultJson 화법 주의, 아래 관찰 2).
- 토큰 사용량·컨텍스트 압축 후 행동: 관측 불가 (미측정).
- 심미 판단("보기 좋게"): 호스트 1차 판정, 사용자 확인 필요.
- 워크스페이스: 시나리오별 분리 (`dogfood-a2/b/c`, `.procforge/` 백업 대신 분리로 세션 격리).

- 모델 2종: 상위 1 (예: Opus급), 저가 1 (예: Haiku급). 모델명·버전 기록.

## 2. 시나리오

- (a) 월간보고서: "`a.pptx`를 9월 월간보고서로 완성해라. 실적은 `sales-2026-09.xlsx` 기준,
  금액은 부가세 제외(세전)로 표기."
- (b) 엑셀 집계 → 표 1장: "`sales-2026-09.xlsx`를 제품별로 집계해 `a.pptx` 2번 슬라이드 표를 갱신해라."
- (c) 모호한 요청: "`a.pptx`를 보기 좋게 다듬어라." (분해 난이도·질문 유도 측정용)

각 시나리오 × 모델 2종 = 6회 실행. 실행 전 `.procforge/` 백업(세션 섞임 방지).

## 4. 확정 세션 후속 실행 (각 시나리오 완주 세션 대상)

- `procforge test --session <sid> --mode replay` → 결과 (전 constraint pass 여부)
- `procforge test --session <sid> --mode passthrough` → drift 발생 여부와 내용
- 기록: replay/passthrough 소요 시간, 불일치 지점

## 5. 결론 (측정 후 작성)

- 관찰 (호스트=단일 모델, 2026-10-10):
  1. 카탈로그 cold start: 외부 MCP 서버 기동이 5s 수집 타임아웃을 초과하면
     초도 pf_start가 빈 카탈로그+경고로 진행된다. 재시도하면 캐시/웜업으로 해소.
     (외부 요인. 타임아웃 상향은 별도 판단.)
  2. xlsx 등 도구 미지원 바이너리는 호스트 대역 집계가 불가피하다. 이때 resultJson에
     계산값을 넣으면 record/replay의 auto 제약을 깨뜨린다. 호스트 화법: 계산값은
     resultSummary에만, resultJson은 도구 출력과 일치하는 키만 (또는 생략).
  3. 무의미한 var ref (`edits` → `${params.month}`)도 schema·validator를 통과한다.
     dep_without_dataflow 경고가 검출망 역할을 했다. (문구 1건 적용.)
  4. passthrough drift 3건 전부 true positive (호스트 요약 paraphrase·바이너리 요약).
     drift 검출 자체는 정상 동작.
  5. llm_rubric 부착 후에는 매 보고에 rubricReasons가 필요하고, 재시도 한도 소진 시
     needs_human→reopen→advise→retry 경로로 복구 가능하다 (동작 확인).
     단 advise 문구가 llm_rubric을 새로 부착할 수 있어 복구 루프가 길어진다.
  6. [버그, 코드 수정 필요 → 별도 마일스톤] file_exists auto 제약이 첫 attempt의
     fixture 경로를 고정(pin)한다. 재보고(reopen/retry/edit_args 후)는 새 attempt
     기준으로 ingest되므로 구 키가 contents에 없어 항상 실패한다.
     사례: (b)-1.1 2회, (c)-1.2 1회. 우회는 pf_edit_node로 해당 auto 제거.
     M3.5 범위(문구·description) 밖이므로 수정하지 않고 분리한다.
- 도구 설명/instruction 수정 제안 (구체적 문구, 적용됨):
  - pf_confirm_leaf description에 1문 추가: "var/generated ref는 실제 params 키·
    노드 출력이어야 하며, 무관한 ref는 재바인딩을 깨뜨린다." (관찰 3 대응, M3.5-2)
- M4 설계 반영 사항:
  1. file_exists pin 버그 (관찰 6) → 별도 마일스톤에서 수정 (manifest/source 기준 판정 등).
- 코드 수정 범위 준수: 본 기록 + description 1문 외 수정 없음.
  driver(`packages/local/dogfood-call.mjs`, 일회용)는 삭제.

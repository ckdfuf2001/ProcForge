# M3.5 실사용 테스트 (dogfood) 계획·기록

상태: 하네스 준비 완료, 실측은 사용자 환경에서 수행 (실제 OpenCode + 실제 모델 필요).
측정 후 "결론" 절을 채우고, 코드 수정은 instruction 문구·description에 한정한다.

## 1. 환경

- 호스트: 실제 OpenCode (procforge local MCP 등록, `docs/M2-manual.md` 절차).
- 모델 2종: 상위 1 (예: Opus급), 저가 1 (예: Haiku급). 모델명·버전 기록.
- PPT MCP 서버: `knorq-ai/pptx-mcp-server` 권장.
  - 선택 근거: python-pptx 기반, PyPI 배포(`pip install 'pptx-mcp-server[mcp]'`),
    읽기+편집 37종, 레이아웃 검증(`pptx_check_layout`) 내장, PowerPoint 설치 불필요.
  - 대안: `dosev-ai/mcp-office`의 pptmcp (쓰기 게이트·COM 선택 지원),
    `Gyangu/Office-PowerPoint-MCP-Server` (기본 CRUD).
- 샘플: `examples/dogfood/` (`make-samples.py`로 재생성)
  - `a.pptx`: 표지 + 9월 실적 요약(표) + 10월 전망(빈 틀)
  - `sales-2026-09.xlsx`: 9월 일자별 제품/수량/단가/금액(부가세 포함) 가짜 데이터

## 2. 시나리오

- (a) 월간보고서: "`a.pptx`를 9월 월간보고서로 완성해라. 실적은 `sales-2026-09.xlsx` 기준,
  금액은 부가세 제외(세전)로 표기."
- (b) 엑셀 집계 → 표 1장: "`sales-2026-09.xlsx`를 제품별로 집계해 `a.pptx` 2번 슬라이드 표를 갱신해라."
- (c) 모호한 요청: "`a.pptx`를 보기 좋게 다듬어라." (분해 난이도·질문 유도 측정용)

각 시나리오 × 모델 2종 = 6회 실행. 실행 전 `.procforge/` 백업(세션 섞임 방지).

## 4. 확정 세션 후속 실행 (각 시나리오 완주 세션 대상)

- `procforge test --session <sid> --mode replay` → 결과 (전 constraint pass 여부)
- `procforge test --session <sid> --mode passthrough` → drift 발생 여부와 내용
- 기록: replay/passthrough 소요 시간, 불일치 지점

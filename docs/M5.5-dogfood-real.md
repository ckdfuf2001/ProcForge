## 1. 스스로 until/map/state로 나누는지 — 예, 1회 자가 수정 포함
- 루트 → 3분할 (목록 until / 상세 map / 누적 state). instruction 문구
  ("항목 반복은 map, 페이지는 until, 지난 실행 기억은 state")가 직접 효력.
- 자가 수정 1건: 1.2(map)가 until 출력(페이지 배열)을 그대로 over할 수 없어
  1.2를 재분할 (1.2.1 평탄화 script + 1.2.2 상세 map). instruction은 이
  불일치를 예고하지 않음 — 모델이 템플릿 작성 시점에 발견.
- offset 페이징의 `+1` 연산이 ref로 불가 → until 본문은 script가 담당
  (cursor `$self` ↔ `nextCursor` carry). instruction에 이 우회가 없음 (M6 후보 h).

## 2. pf_advise 없이 노드만 고쳐지는지 — 예, 그러나 2건 손실
- `pf_edit_node` 수정 7회 모두 즉시 반영 (count 제약·map·until·stateWrites 지정).
- 손실 1: `json_path_exists`가 `{"ids":[...]}` / `{"newIds":[...]}`에 2회 연속

  `retriesLeft: 0`까지 감소, 결국 제약 제거 후 확정. repo checker 코드와
  불일치 의심 (버전 skew, M6 후보 c).
- 손실 2: `pf_edit_node`의 map/until/stateWrites 입력이 조용히 버려짐
  (get_node로 확인). finalize는 오히려 until 검증을 요구해 모순
  (`$self outside until`). Pf 백엔드가 M5.5 이전 버전 (M6 후보 d).
- `needs_human` 미발생 (llm_rubric 제약 없음). advise 경로는 미검증.

## 4. approve를 손대지 않고 그대로 — 아니오 (map 템플릿)
- `approve ... --node 1.2.2` 생성분 그대로 → exit 3 (deny).
  원인: 템플릿 fixed 값의 리터럴 `${item}`이 실행 시 실제 id와 정확 비교됨.
  `$prefix` 수기 교체 후에만 통과. approve가 `${...}` 포함 fixed 값을
  `$prefix`로 제안해야 함 (M6 후보 b).
- 추가로 CLI ref 버그 2건 (M6 후보 a):
  - `approve hn-daily` (bare name) → run-approve 모드로 오판 (detector가
    `procedures/` 접두·`.json`만 절차서로 인정).
  - `approve <file>.json` → `resolveProcedureRef`의 `..`,`..` 규칙이 dir을
    `procedures/`로 잡아 approvals.json·state.json·readScript 기준 전부 어긋남.
    이 오염으로 approvalHash가 마커로 계산되어 전부 stale이 됨 (4.4-3이 잡은
    것과 같은 증상). bare-name 직접 app 호출로 우회 후 정상 해시 확인
    (`804109bf…`).
  - `run procedures/<name>` 문서 문구도 같은 이유로 실패 (EISDIR/`procedure 없음`).

## 결론

  구조를 고친다 (평탄화 1건). pf_edit_node 부분 수정도 동작한다.

- approvals는 손댄 뒤에야 통과한다 (b + a). 무인 2회차 누적·exit 표·잠금은
  실전에서 동작한다.
